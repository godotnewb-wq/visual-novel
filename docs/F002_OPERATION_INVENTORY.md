# F-002 P2.1 operation and side-effect inventory

Date: 2026-11-25. Reviewed source: `writer-manager`, `6788dfb0c6ea979a60e7ef35fb0eaf19ef73771c`, plus the existing
P2.0 test/documentation changes. This is a source inventory and proposed integration map, not implemented Dual-call behavior.
See F002_TURN_CONTRACT.md for the proposed typed contract and validation rules.

## Current ownership

`src/main/index.ts`'s `IPC.chat` handler validates the request, derives content for the state, builds the character
prompt, runs routed completion/tools, parses directives, and returns `ChatResponse`. Main validates proposals;
`src/renderer/src/App.tsx`'s `send` applies game effects and publishes scene/UI state. Main does not own a separately
persisted authoritative game session. Two awaited requests alone would not make these renderer changes atomic.

The prepared content path is `withHousing(personalise(content, state.player.name), state)`, followed by existing NPC
or mask transforms where applicable. All new planning/validation must use the same derived content and captured state.

Important baseline details: `sceneDestinations` checks the captured current location/open state. The move tool
calculates delayed time for `moveClash`, but does not separately rebuild that destination list after waiting.
`passSceneTime` caps added hours and checks whether the game was already over; it does not clamp the resulting time
to the final hour. P2.1 does not silently retune either rule. Any stricter behavior needs its own approved change.

## Surrounding state, persistence, and external effects

- `send` adds a provisional undo entry, stages the submitted message, handles due drama arrivals, and resets several
  UI notices. Its error path removes the tentative undo and restores the pre-request scene; some arrival state was
  already applied. The proposed Dual-call checkpoint stages turn-caused arrivals too; Legacy keeps its baseline.
- Scene-driven met/stranger/first-line effects must observe committed scene state, not the pending Writer draft.
  Existing recorded opening lines, direct Schedule/Accept actions, cutscenes, and Goodbye-without-reply paths do not
  become two-call generations merely because a scene uses Dual-call mode. Preserve their deterministic entry/exit behavior.
- `savable` ALREADY omits an unanswered player line and that line's provisional undo entry before packing. Preserve
  this working safeguard; add protection for the whole prepared turn rather than claiming unanswered text is saved today.
- `leaveScene` stores the departure cutoff at the reply's final message count. A departing character hears the entire
  reply in which she leaves. Arrival/witness boundaries need to respect existing drama logic as well as departures.
- Gift/item/relic/scheduling/Accept/Decline UI actions can change state before or independently of `send`. Freeze new
  foreground changes while a Dual-call turn is pending; the checkpoint starts AFTER any already committed user action.
  Cancellation must not refund an already given gift or discard an accepted plan as a side effect of cancelling its reply.
- `onAnimationEnd` is a foreground presentation mutation; defer it while pending or apply a compatible visual completion
  event under the session reducer. It must not invalidate a turn merely because a video ended or resurrect a cleared pose.
- Response audio, catchphrases, notices, debug prompts, completion flags, and `earnedByLeaving` are published after commit.
  Achievements use their existing durable/idempotent semantics; undo does not unplay sound or revoke achievements today.
- Independent feed/news/courier/photo results can arrive while pending. Preserve the exact `turns.ts` `KEPT_ACROSS` set
  on undo; merge or buffer independent results during commit without overwriting them with an old whole-state snapshot.
- Autosave watches state/scene. Main validates save schemas; `resumeSavedGame` reconciles content and keeps undo only for
  a resumable scene. New optional metadata must survive this entire path and `packTurns`/`unpackTurns`, including ACC-001 coverage.
- Summary/evaluation, spending, durable discoveries, rapport, intimacy/bonds/ties, shift pay, daily outfits, sleep settlement,
  end-of-scene contacts/courier, special dances, and summary editing/retry remain their existing completion systems.
  Memory retry changes wording/level only; ledger context must not re-award settled effects.

## Explicit exclusions

Courier `reveal_fact`/`excuse_shift`, outings, news/feed generation, character drafting, ComfyUI, and non-turn model
routing stay on their current paths. No arbitrary state patching, new meters, new ordinary-NPC long-term memory,
character retuning, dice tool, additional presentation model, or game-rule cleanup is included in this contract stage.
